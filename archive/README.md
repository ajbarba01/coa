# archive/ — parked feature code (reference only)

Nothing in this directory compiles, is imported, or is part of the product. It is
excluded from typechecking, linting, formatting, tests, dependency cruising, and the
docs index. Each entry below records what the code was, why it was parked, and the
future work that might revive it. When a feature is revived, its entry moves back into
the tree as ordinary code and the row is removed here.

| Entry | What it was | Why parked | Revival path |
|---|---|---|---|
| `decision-log/` | The decision-log / provenance layer: an append-only decision log with vouch records and a subtractive-change feed projected from governance WAL frames, the self-modification guard, and their wire schema — read back through the `getDecision`/`why` RPC verbs, the `coa why` / `coa decision` CLI commands, and the `why`/`get_decision` agent tools (all removed with it). | The write side never ran, so every read returned empty forever. | None planned (deliberate). |
| `flag-extensions/` | Two flag-pipeline extensions, with their tests: `AutoPatcher`, a planner that turns a flag's deterministic fix into a visibly applied, one-action-revertible patch (demoting fixes that overreach their span or flip-flop), and `ReminderPolicy`, which picks the single highest-authority registered rule to re-surface when the agent is about to slip past it. | Neither was ever constructed or registered — the live flag pipeline (close gate, user flag feed, per-tool deny) never enabled them. | Someday: flag auto-fix / reminders. |
| `bundle-importer/` | The bundle import pair, with their tests: `importBundle`, a pure wrap of a single Claude-Code `SKILL.md` into one config Piece (recognized front-matter keys map to typed fields, everything else rides through verbatim), and `versionGate`, which diffs a bundle's declared public surface against its prior manifest, classifies the change as a major/minor/patch bump, and reports the dependent-role blast radius on a breaking change. | No CLI verb, RPC handler, or UI path ever called either — their only consumers were their own tests and the package barrel export. | The skills/MCP/plugin arc (reference material). |
| `signal-bus/` | The signal bus, with its test: a bounded in-memory ring of change events under OpenTelemetry-style dotted names, written by the kernel once per applied frame and exposed through a predicate query view. | Write-only in production — the kernel recorded a signal for every frame, but the read view had zero callers anywhere, not even a test. | None planned. |
| `undo-plumbing/` | The undo plumbing behind the checkpoint timeline, with its tests: `Timeline.pin`/`unpin` (the human bookmark that made a checkpoint hold a WAL retention floor), `Timeline.retentionFloor` (the compaction-safety floor over consumer cursors and pinned checkpoints), `rewindPathspec` (working-tree re-materialization via `git restore --source`, never history), and the kernel facade methods delegating to them. | Zero callers outside their own tests — no RPC verb, CLI command, or UI control ever invoked pin/unpin/rewind, and no compaction code ever read the floor. The live timeline (`checkpoint`/`listTimeline`, read by the console Timeline panel) stays in the tree. | Someday: turn-level undo. |
