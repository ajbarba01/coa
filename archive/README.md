# archive/ — parked feature code (reference only)

Nothing in this directory compiles, is imported, or is part of the product. It is
excluded from typechecking, linting, formatting, tests, dependency cruising, and the
docs index. Each entry below records what the code was, why it was parked, and the
future work that might revive it. When a feature is revived, its entry moves back into
the tree as ordinary code and the row is removed here.

| Entry | What it was | Why parked | Revival path |
|---|---|---|---|
| `decision-log/` | The decision-log / provenance layer: an append-only decision log with vouch records and a subtractive-change feed projected from governance WAL frames, the self-modification guard, and their wire schema — read back through the `getDecision`/`why` RPC verbs, the `coa why` / `coa decision` CLI commands, and the `why`/`get_decision` agent tools (all removed with it). | The write side never ran, so every read returned empty forever. | None planned (deliberate). |
| `flag-extensions/` | Two flag-pipeline extensions, with their tests: `AutoPatcher`, a planner that turns a flag's deterministic fix into a visibly applied, one-action-revertible patch (demoting fixes that overreach their span or flip-flop), and `ReminderPolicy`, which picks the single highest-authority registered rule to re-surface when the agent is about to slip past it. The `EscapeEvent` wire schema (the reminder-trigger event `ReminderPolicy` consumed) followed it here; the live `Reminder` shape stays in the tree. | Neither was ever constructed or registered — the live flag pipeline (close gate, user flag feed, per-tool deny) never enabled them. | Someday: flag auto-fix / reminders. |
| `bundle-importer/` | The bundle import pair, with their tests: `importBundle`, a pure wrap of a single Claude-Code `SKILL.md` into one config Piece (recognized front-matter keys map to typed fields, everything else rides through verbatim), and `versionGate`, which diffs a bundle's declared public surface against its prior manifest, classifies the change as a major/minor/patch bump, and reports the dependent-role blast radius on a breaking change. The `BundleManifest` wire schema (the versioned role-as-bundle manifest both consumed) followed it here. | No CLI verb, RPC handler, or UI path ever called either — their only consumers were their own tests and the package barrel export. | The skills/MCP/plugin arc (reference material). |
| `signal-bus/` | The signal bus, with its test: a bounded in-memory ring of change events under OpenTelemetry-style dotted names, written by the kernel once per applied frame and exposed through a predicate query view. | Write-only in production — the kernel recorded a signal for every frame, but the read view had zero callers anywhere, not even a test. | None planned. |
| `undo-plumbing/` | The undo plumbing behind the checkpoint timeline, with its tests: `Timeline.pin`/`unpin` (the human bookmark that made a checkpoint hold a WAL retention floor), `Timeline.retentionFloor` (the compaction-safety floor over consumer cursors and pinned checkpoints), `rewindPathspec` (working-tree re-materialization via `git restore --source`, never history), and the kernel facade methods delegating to them. | Zero callers outside their own tests — no RPC verb, CLI command, or UI control ever invoked pin/unpin/rewind, and no compaction code ever read the floor. The live timeline (`checkpoint`/`listTimeline`, read by the console Timeline panel) stays in the tree. | Someday: turn-level undo. |
| `grounding-producer/` | The symbol-grounding producer, with its test and wire schemas: `ground()` checked every symbol-naming tool call against the project symbol index and, on a near-miss, appended an advisory grounding block (rename/typo suggestions with confidence and a freshness stamp) to the tool return via the enrich decorator. The `RankedCandidate` wire schema followed it here when the kernel's caller-less `fuzzyMatch` read and its `FuzzyIndex` were deleted outright (git history is the recovery path). | It could only query the permanently-empty symbol index — nothing in production ever populated the symbol table, so every lookup missed, every fuzzy match returned nothing, and the producer returned no block on every call. The flags half of the enrich decorator stays in the tree. | The tool repair + grounding arc (reference material). |
| `spec-conformance/` | The spec-conformance pair of the context engine, with their tests: `publishGenerationSeam`, which regenerated each declared generation target, declared the symbols it would produce so a not-yet-generated type is not a false miss, and asserted the regenerate-provenance and `governed-by` authority edges; and `governanceFor`, the read half, which resolved the symbol a tool call names to the registered constraints governing it over those same edges. | Neither end was ever wired: no daemon or producer-assembly path called the publisher, so no `governed-by` edge was ever written, and nothing called the reader that would have consumed one. Their only callers were their own tests. The drift-detection constraint and the origin-anchor notice — the parts of the context engine that do run — stay in the tree. | The spec-conformance arc: revive both together, and only once something in production writes the authority edge. |
| `code-health/` | The code-health signal producer, with its test: `health()` composed the cheap, language-agnostic signals riding the kernel's existing projections (cycle tangle, coupling fan-in/fan-out, churn and hotspot from the change log, size) into a worst-of, never-scored profile, with conservative starting cut-points meant to be calibrated later. | Never constructed or registered — no producer-assembly path, RPC verb, or console panel ever asked for a profile. Its composition helper (`composeProfile`, with its own test) is parked here too — `health()` was its only consumer, so it became caller-less the moment this moved. | Someday: a code-health surface. It needs a caller (a console panel or a producer registration) and the calibration pass its cut-points were always waiting on. Both files revive together. |
| `capability-profile/` | The backend port manifest wire shape (`CapabilityProfile`): which optional ports a backend implements, what each degrades to when absent, and the port-interface version it was built against. | It lost its last consumer when the runtime-adapter port shrank to the methods the loop actually drives — after that nothing built a profile and nothing read one, leaving a single schema-parse assertion in the shared smoke test as its only caller. The per-agent tool intents and the enforced per-session sandbox set stay in the tree. | A second backend generation where adapters differ in optional capabilities enough to need negotiation rather than the current uniform port. |
| `sdk-probes/` | The exploratory half of the Claude adapter's SDK control-probe suite: offline and live probes measuring levers no shipped code uses — tool aliasing, the SDK-native subagent/delegation plane (`agents`, subagent hooks, `taskBudget`, `forwardSubagentText`), compaction control, SDK session stores and file checkpointing, inference-URL redirection, process-level escape hatches (`extraArgs`, `executableArgs`, `betas`, transport smuggling), and structural scans of the compiled CLI binary. | The probes answered the design questions they were written for, and the answers were built the other way (subagents are coa's own governed sessions, spend is coa's own ledger, the bounded tool floor removes native delegation) — nothing shipped relies on them. The load-bearing probes (permission seam, hooks, bounded tool surface, session lifecycle) stay in the tree. | None needed — the findings get distilled into docs in a later stage. |
